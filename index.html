glibc_2.23malloc()函数逻辑

我们经常会遇到malloc特定字节，而实际上分配到的却不是申请的字节数量的情况：
malloc(8);
实际上的堆布局：

我们需要一篇文章解释malloc的真实行为。

malloc()实际是宏定义，比如用户调用malloc(8)时会经过如下的调用链
malloc(8)
├── __libc_malloc(size) // malloc 封装函数，统一入口
│ ├── _int_malloc(arena, size) // 核心分配逻辑（ptmalloc2 核心）
│ │ ├── 1. 检查 tcache // 线程本地缓存（最高优先级）
│ │ │ ├── tcache_get(8) // 尝试从 tcache 中取 8 字节的块
│ │ │ └── 若命中：直接返回，无后续步骤
│ │ ├── 2. 检查 fastbin // 快速链表（次优先级，< 64B）
│ │ │ ├── _malloc_consolidate(arena) // 若 fastbin 无可用块，尝试合并碎片
│ │ │ └── fastbin_get(8) // 尝试从 fastbin 取 8 字节块
│ │ │ └── 若命中：返回，无后续步骤
│ │ ├── 3. 检查 unsorted bin// 未分类链表（从 free 释放的块先进入这里）
│ │ │ ├── 遍历 unsorted bin，匹配 8 字节块
│ │ │ └── 若命中：移到对应 bin，返回
│ │ ├── 4. 检查 small bin // 小内存链表（16B~64KB）
│ │ │ ├── smallbin_get(8) // 尝试从 small bin 取块
│ │ │ └── 若命中：返回
│ │ ├── 5. 尝试扩展堆 // 以上都失败，向内核申请新堆内存
│ │ │ ├── sysmalloc(8) // 堆扩展核心函数
│ │ │ │ ├── _int_realloc // （可选）调整堆大小
│ │ │ │ └── sbrk(0) // 先获取当前堆顶地址
│ │ │ │ └── brk(new_brk) // 内核系统调用，扩展堆
│ │ │ └── 分配新块并返回
│ │ └── 6. （极端情况）mmap // 若 brk 失败（如堆地址耗尽），用 mmap 分配
│ │ └── mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0)
│ └── 返回分配的内存地址
└── 用户拿到 p

最核心导致堆中实际堆块的大小与我们malloc的不同的函数是位于_int_malloc()最前面的checked_request2size()函数
下面是其定义，实际上是个宏

解释一下这一些宏

先来检查申请的堆块大小是否合法
然后：
如果申请的大小 + SIZE_SZ + MALLOC_ALIGN_MASK < MINSIZE，返回的是MINSIZE
否则返回16字节对齐后的堆块。MALLOC_ALIGN_MASK = 15，& ~MALLOC_ALIGN_MASK等价于& 0xfffffff0
在当前版本的glibc，MINSIZE是32字节，size_t是8字节。
我们可知申请8字节得到的应是32字节

glibc_2.23下的fastbin_dup_into_stack

doublefree是我们一开始学堆利用时最常听到的一个词，这个示例解释了doublefree其实不是目的，而是桥梁。
这个示例讲述了用doublefree使得malloc不再份额份分配堆内存，而是返回一个栈地址。

构造fastbin布局
a->b->a->null
经过两次malloc：
a->null
此时手上有a和b的地址，且a和b都是allocated。能够合法修改a的fd。
如果不经过doublefree，直接申请a，修改其fd，free后其fd会被glibc覆盖，等于白改。
所以这就是为什么要doublefree。doublefree只是桥梁，不是目的。
stack_var被设置为了0x20，这个地方表示堆块的size，符合fastbin要求，经过malloc检测，那么，malloc自然就会返回&stack_var + 8的地址。
&stack_var - 8: glibc看到的堆块头部
&stack_var: 堆块头的size字段 设置为0x20，最后标志位为0,表示堆块未被使用
&stack_var + 8: 用户层面看到的堆块头部，由malloc返回给用户。

glibc_2.23下的house_of_orange以及FSOP

示例来自how2heap：

1.伪造topchunk_size，满足页对齐条件
页对齐：一个地址是 “页对齐” 的，当且仅当：地址 % 0x1000 == 0（地址除以 0x1000 余数为 0）。
Top Chunk起始地址 + Top Chunk实际大小 = 页对齐地址

2.触发 sysmalloc，将原 top chunk 送入 unsorted bin
申请一个比伪造后的 top chunk size 更大的 chunk（如 0x100）
流程：
_int_malloc 发现 top chunk 不够 → 调用sysmalloc
sysmalloc 判断需用 brk 扩展堆 → 原 top chunk 被 free
原 top chunk 因 size>fastbin 范围，进入 unsorted bin
结果：无 free 也获得 unsorted bin 控制权

3.Unsorted Bin Attack：篡改_IO_list_all
用漏洞修改 unsorted bin 中 chunk 的bk 指针为_IO_list_all - 0x10
再次触发 malloc（如申请 small bin 大小 chunk）
unsorted bin 处理时执行：*(bk+0x10) = fd → _IO_list_all = main_arena
结果：_IO_list_all 被劫持，指向 main_arena + 88的位置
我们在阅读例子的时候要确定smallbin[4]的位置，因为0x61大小的块最终要被分配到这个位置。
我们并不关心main_arena中：
mchunkptr bins[NBINS * 2 - 2];
相对于main_arena_base的偏移究竟是多少，我们可以确定的是main_arena + 88的位置就是mchunkptr last_remainder这个指针。
其紧接着就是bins[NBINS * 2 - 2]数组。
在topchunk刚被分配入unsortedbin时，unsortedbin中只有topchunk一个块，这时它的fd和bk都会指向这个last_remainder指针。

4.要想在_IO_flush_all_lockp遍历_IO_list_all时遍历到我们伪造的FILE，我们有2个选择
一是直接把top放置在main_arena+88的位置，二是把top放置在main_arena+88这个FILE对应的下一个FILE，即struct _IO_FILE *_chain的位置。
这个位置相对于FILE结构体头部的偏移为0x60，对main_arena+88的偏移也是0x60字节，即main_arena+184的位置

伪造的FILE需要满足的条件：
（1） 将 mode 设为 0：满足 fp->_mode <= 0
（2） 将 write_base 设为 2，write_ptr 设为 3：满足 fp->_IO_write_ptr > fp->_IO_write_base
（3） 最后，将跳转表（jump table）指针指向我们可控的内存区域，并将 system 函数地址放入该区域。
跳转表指针紧邻 FILE 结构体之后：
base_address+sizeof(FILE) = jump_table

     （3-a） _IO_OVERFLOW 会调用跳转表偏移 3 处的指针：jump_table+0x18 == winner（注：winner 应为 system 函数地址）

main_arena + 184这个位置，对应smallbin [4]，对应的的堆大小90-98，故而把堆大小改成0x61。

5.malloc(10)触发整个攻击链
malloc 进入主逻辑，优先检查 unsorted bin
10 字节远小于旧 Top Chunk 的实际大小（0x60=96 字节），malloc 判定 “该块不适合本次分配”
malloc 将旧 Top Chunk 归类到 smallbin [4]（main_arena + 184）
malloc 检查 smallbin [4] 中块的合法性，触发堆校验失败
abort () 触发 _IO_flush_all_lockp 遍历 _IO_list_all
_IO_list_all（被覆写）→ main_arena + 88（遍历到的第一个 FILE）
↓（偏移0x60）
_chain（main_arena+184）
↓（存储的内容）
旧Top Chunk地址（top）→ 你伪造的FILE结构体
↓（遍历到的第二个 FILE）
调用_IO_OVERFLOW → system(“/bin/sh”)

glibc_2.23下的unsorted_bin_attack

示例：

示例讲述了一个向栈中写入数据的例子利用 unsorted bin 双向链表的整理逻辑，篡改chunk的bk指针，让malloc操作时将链表的fd值（通常是libc地址）写入指定目标地址。
一句话来说，bk的fd是当前的fd，fd的bk是当前的bk。
bk的fd从哪里来找呢？在堆块头+16字节的地方。
glibc的工作：bk+16 = fd fd+24 = bk
即p[1]=(unsigned long)(&stack_var-2)的意义。

glibc_2.23下的堆利用链fastbin_dup_consolidate

示例来自how2heap

核心：malloc在分配大堆块（>=0x400）时会触发malloc_consolidate()，会把fastbin中的空闲堆块分配到topchunk或unsotedbin中，取决于堆块与topchunk是否相邻

最上面的那个0x410的堆块是什么？是当程序第一次调用 malloc/calloc 时，glibc 不会只分配你需要的小内存，而是会向操作系统预申请一块较大的连续内存（arena），作为堆的「初始池」，后续的小内存分配都从这个池子里扣，避免频繁调用系统调用（brk/mmap）影响效率。

doublefree p1 malloc p4后,p3和p4都指向相同的第二个堆块，且p3和p4从未被释放过

整体思路
申请0x40fastbin堆块（p1）——申请0x400大堆块触发malloc_consolidate()，此时p1指向topchunk顶端，之后得到p3,与p1相同都指向0x410的堆块——doublefree p1，0x400堆块融合进topchunk——继续申请0x400堆块（p4）得到p4=p3
