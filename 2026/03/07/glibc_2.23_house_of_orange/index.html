glibc_2.23下的house_of_orange

示例来自how2heap：

1.伪造topchunk_size，满足页对齐条件
页对齐：一个地址是 “页对齐” 的，当且仅当：地址 % 0x1000 == 0（地址除以 0x1000 余数为 0）。
Top Chunk起始地址 + Top Chunk实际大小 = 页对齐地址

2.触发 sysmalloc，将原 top chunk 送入 unsorted bin
申请一个比伪造后的 top chunk size 更大的 chunk（如 0x100）
流程：
_int_malloc 发现 top chunk 不够 → 调用sysmalloc
sysmalloc 判断需用 brk 扩展堆 → 原 top chunk 被 free
原 top chunk 因 size>fastbin 范围，进入 unsorted bin
结果：无 free 也获得 unsorted bin 控制权

3.Unsorted Bin Attack：篡改_IO_list_all
用漏洞修改 unsorted bin 中 chunk 的bk 指针为_IO_list_all - 0x10
再次触发 malloc（如申请 small bin 大小 chunk）
unsorted bin 处理时执行：*(bk+0x10) = fd → _IO_list_all = main_arena
结果：_IO_list_all 被劫持，指向 main_arena + 88的位置
我们在阅读例子的时候要确定smallbin[4]的位置，因为0x61大小的块最终要被分配到这个位置。
我们并不关心main_arena中：
mchunkptr bins[NBINS * 2 - 2];
相对于main_arena_base的偏移究竟是多少，我们可以确定的是main_arena + 88的位置就是mchunkptr last_remainder这个指针。
其紧接着就是bins[NBINS * 2 - 2]数组。
在topchunk刚被分配入unsortedbin时，unsortedbin中只有topchunk一个块，这时它的fd和bk都会指向这个last_remainder指针。

4.要想在_IO_flush_all_lockp遍历_IO_list_all时遍历到我们伪造的FILE，我们有2个选择
一是直接把top放置在main_arena+88的位置，二是把top放置在main_arena+88这个FILE对应的下一个FILE，即struct _IO_FILE *_chain的位置。
这个位置相对于FILE结构体头部的偏移为0x60，对main_arena+88的偏移也是0x60字节，即main_arena+184的位置

伪造的FILE需要满足的条件：
（1） 将 mode 设为 0：满足 fp->_mode <= 0
（2） 将 write_base 设为 2，write_ptr 设为 3：满足 fp->_IO_write_ptr > fp->_IO_write_base
（3） 最后，将跳转表（jump table）指针指向我们可控的内存区域，并将 system 函数地址放入该区域。
跳转表指针紧邻 FILE 结构体之后：
base_address+sizeof(FILE) = jump_table

     （3-a） _IO_OVERFLOW 会调用跳转表偏移 3 处的指针：jump_table+0x18 == winner（注：winner 应为 system 函数地址）

main_arena + 184这个位置，对应smallbin [4]，对应的的堆大小90-98，故而把堆大小改成0x61。

5.malloc(10)触发整个攻击链
malloc 进入主逻辑，优先检查 unsorted bin
10 字节远小于旧 Top Chunk 的实际大小（0x60=96 字节），malloc 判定 “该块不适合本次分配”
malloc 将旧 Top Chunk 归类到 smallbin [4]（main_arena + 184）
malloc 检查 smallbin [4] 中块的合法性，触发堆校验失败
abort () 触发 _IO_flush_all_lockp 遍历 _IO_list_all
_IO_list_all（被覆写）→ main_arena + 88（遍历到的第一个 FILE）
↓（偏移0x60）
_chain（main_arena+184）
↓（存储的内容）
旧Top Chunk地址（top）→ 你伪造的FILE结构体
↓（遍历到的第二个 FILE）
调用_IO_OVERFLOW → system(“/bin/sh”)
